# 会話の参照先・話者の取り違えの改善

更新日: 2026-11-15。ローカル実装と人工会話による検証後、本番へ反映済み。

## 確認した問題

- 表示名が職業や状態を表す文章だと、特定の参加者への質問を一般論として読んでしまう。
- 「君へのあたり」をAIへの言動として読めず、質問者への対応と取り違える。
- 15分の中断や意味的な話題分離でsessionが変わると、保持期限内の以前のやり取りも回答文脈から消える。
- 要約と回答がそれぞれ履歴の先頭から話者番号を振り、履歴窓の移動やAI発言の有無で対応が変わる。
- reply先のAI回答だけを取得し、その回答が返した元の質問は履歴窓外だと欠落する。
- 添付の存在・内容を渡していないのに、画像への指示語を会話の説明で埋めてしまう。

本番の読み取り確認では、対象チャンネルは旧実装の`all`、本人登録プロフィールは0件だった。11月12日の参加制御のローカル実装は稼働版に含まれていなかった。プロフィールが未登録であることと、参加者名や会話の指示先を理解できないことは別の問題として扱う。

## 変更

### 話者と指示語

session IDとauthor IDから作る同一の匿名ラベルを要約・参加判断・回答で使用する。履歴窓が移動しても、AI発言が増えても振り直さない。別sessionでは別ラベルとなる。旧方式の話者参照を含む要約は使用せず、次の要約処理で保持中の本文から再作成する。

参加判断にも表示名と要約に対応する話者ラベルを渡す。回答時には、表示名を参加者名として読むこと、AI宛の「君」「あなた」を質問者へすり替えないこと、呼び掛けを発言者の属性へ変換しないことを明記する。参加者への質問には、見えている具体的な言動の範囲で答える。

### 以前の会話の参照

同じGuild・チャンネルの閉じたsessionから、保持期限内の最大200件を候補にする。直前6件と今回の発言で名前への言及があるときは、その人の発言と前後を最大16件選ぶ。「さっき」「今まで」「覚えて」などの履歴参照だけなら直近12件を候補にする。

モデルへ渡す以前の発言は`EARLIER`と明示し、本文は1件500文字まで、全体は推定1,800 tokensまでとする。現在の発言とreplyの連鎖を優先し、system・設定・要約の実際の推定量と追加指示の予約を差し引いた残りから選ぶ。以前の依頼へ改めて返答する材料としては使わない。無関係な新しい質問には閉じたsessionの本文を加えない。

message delete、forget、本文の保持期限、sessionの保持期限、チャンネルのcontext resetを参照条件へ反映する。他Guild・他チャンネル、リセット前のsessionから復活させない。過去snapshotの参照先を、対象より後の発言から選ばない。

15分空いても、保持期間内で同じsessionへのreplyや「さっきの続き」など明示的な継続表現がある場合は同じsessionを維持する。通常の独立した発言には既存のidle境界を適用する。明示replyは200件の通常参照窓の外でも同じ削除・reset境界を確認して最大3段たどり、AI回答に対応する元の質問も確保する。

### 画像・本人情報

添付のある発言は、添付件数と「内容は未解析」の印を残す。画像だけの発言も保存するが、画像やファイルのバイナリ・URL・ファイル名は新たに取得・保存しない。未解析の画像内容を見たように答えないようにする。画像生成が有効なときは、利用できる`/ai-image`を回答側にも知らせる。

本人登録プロフィールを参照する表現に「私のこと覚えてる？」「俺の活動って知ってる？」も含める。参照対象は引き続き今回の発言者本人だけで、一般的な質問にプロフィールを加える方針へは変更しない。

## 検証

- 自動テスト140件成功。表示名、指示語、参加判断、話者対応、replyの連鎖、idle継続、削除・forget・期限・reset・他チャンネル除外、添付表示を確認。
- `npm run context-smoke`: 架空の表示名・人工会話による実API検証。「この資格勉強中って人」と「今までの君へのあたり」を、当該参加者のAIへの言動として回答できた。実利用者のログは使用せず、Discordへの投稿もしない。
- `npm run quality-smoke`: 既存の挨拶・本人情報・一般意見・笑いの沈黙・占いの5ターンを確認。
- 実APIの参加判断5ケース、lint、Prettier、差分検査も成功。

## 制約・配備

- 本文・要約の既定保持は24時間のまま。期限切れの会話、Botが受信していない履歴、画像の内容は復元しない。長期の人物記憶を新設したものではない。
- 参照は候補件数と語句による選択であり、全履歴に対する意味検索ではない。長い表示名の省略、複数話題、古い前振りの見落としは引き続き評価する。
- トークン量は文字数による保守的な推定。非常に長い今回の発言やreply先は優先するため、全入力について厳密な上限を保証する仕組みではない。
- 人工会話の成功は実グループでの品質保証ではない。
- 本番には先行する参加制御の実装も含めて配備した。保存済みのモデル・effort・応答モードとDiscordコマンドは維持した。`all`から`ambient`への設定変更は今回の配備に含めない。
