# グループチャット参加制御の実装と確認

更新日: 2026-11-12

2026-11-15追記: 以下のローカル実装を会話理解の改善とあわせて本番へ配備した。[配備記録](./12-conversation-context.md#2026-11-15-本番配備)を参照する。以下の「本番未反映」は11月12日時点の記録。保存済みの応答モードは`all`を維持している。

[機能見直し](./10-group-chat-review.md)に基づき、参加判断と回答生成を分離した。ローカル実装と人工会話で検証済み。本番への配備と実際のDiscordグループでの継続評価は別途行う。

## 1. 参加の仕方

- 標準は`ambient`。AI宛のメンションとreplyに応じ、呼ばれていない会話は文脈から参加・沈黙を選ぶ。
- 人間へのreply、短い笑い・相づちだけなら、通常は本文生成へ進まない。
- 明示されていない続きや名前での呼びかけも、直近のAI発言と会話から判断する。
- 自発参加は前回のAI発言から20秒空ける。直接依頼やAIとの続きはこの制限で止めない。
- 沈黙時に本文・検索・typingを出さない。沈黙はjobの`silent`という正常終了として記録する。
- 冗談や感想にも参加できる。回答数を増やすためだけの相づちは投稿しない。
- 無言になったことを理由に、話題や質問を自動投稿するタイマーは持たない。

`mention`は明示的なBotメンションとBotへのreplyのみを応答対象とする。`paused`は新規本文の取り込みと応答を止める。`all`は比較・互換用に維持するが、モデルの`silent`を強制的に返答へ書き換える処理は廃止した。

## 2. 処理順

1. 対象チャンネルの人間の本文と宛先を短期保存する。
2. 連投をまとめ、モード・宛先・経過時間・参加間隔を確認する。
3. 判断が文脈に依存する場合だけ、構造化LLM判定で参加・沈黙と返答対象を選ぶ。
4. 参加するときだけtypingし、必要な検索と本文生成を行う。
5. 投稿直前に最新の会話・モード・session・本文revisionを確認する。
6. 新着があれば最大1回再評価する。人間が回答・解決・撤回していれば取り下げる。
7. 更新が続く場合、自発参加は取り下げる。直接依頼は期限内ならDBへ残し、次のターンで再評価する。
8. 投稿の有無と独立して、発言量に応じて要約を更新する。

時間窓に人間同士の質問とAI宛の依頼が混ざっていても、AI宛の対象だけを本文生成へ渡す。生成中に到着した発言は、直接の返答対象と区別して参加判断の材料にする。

話題分類中に新着があった場合はsessionの自動分割を見送る。別々の宛先が混ざったターンも一括分割しない。完全な複数話題の自動管理は引き続き将来課題とする。

## 3. 設定と既存環境の移行

新規構成とモード省略時の既定は`ambient`。既存のYAMLに明記したモード、SQLiteのoverride、停止前の復帰先は自動上書きしない。

既存の対象チャンネルを通常の参加方針へ変更する場合は、管理者が次を実行する。

```text
/ai-mode mode:ambient
```

設定ファイルにも`discord.channels[].mode: ambient`を指定する。永続化済みのDiscord側overrideがある場合はその指定が優先される。`/ai-status`で有効なモードを確認する。今回の実装作業で本番設定は変更していない。

```yaml
conversation:
  ambientCooldownSeconds: 20
  ambientMaxAgeSeconds: 45
  directRequestMaxAgeSeconds: 180
  maxPendingMessages: 50
```

- 45秒より古い自発参加候補は、後から返答として消化しない。
- 明示的なメンション・replyの依頼は最大180秒の間再評価する。
- キュー上限では直接依頼を優先する。雑談は短期文脈へ保持したまま応答候補から外し、上限で入りきらない直接依頼はDBへ残して後から拾う。
- 既存DBには宛先情報と無効化用revisionを起動時に追加する。本文と既存設定を削除するmigrationは行わない。
- 旧形式の未処理メッセージも、保存済み本文のBotメンションや保持中のreply先から宛先を復元して再判定する。

## 4. 記憶と障害

沈黙が続いた場合も、人間の新規発言数が既定12件に達すれば要約する。AI自身の回答も要約対象にし、以前の要約を合わせて流れを保つ。編集・削除・forgetで関連要約を無効化し、要約APIの待機中に削除された内容を保存し直さない。

自発参加の判定・本文生成・出力検査が失敗した場合は黙る。直接依頼の生成失敗だけを短く通知し、同じチャンネルの障害通知は60秒間隔で抑制する。判定理由・状態・API statusは記録し、会話本文を通常ログへ追加しない。

## 5. 検証

自動テスト121件、lint、全ファイルのformat check、差分の空白検査が成功した。`quality-smoke`も実APIで成功し、直接の挨拶・質問・占いには応じ、単独の`www`には投稿しないことを確認した。

```bash
npm test
npm run lint
npm run format:check
npm run participation-smoke
```

`participation-smoke`は人工会話だけをClaude APIへ送り、Discord接続・DB・Web検索・チャンネル投稿は行わない。API利用料金は発生する。

実APIで次の5ケースの参加判断を確認した。

| ケース                                 | 期待 | 結果 |
| -------------------------------------- | ---- | ---- |
| 人間同士で進行中の相談                 | 黙る | 合格 |
| AIの説明への暗黙の追加質問             | 参加 | 合格 |
| メンション記法を使わないAIへの呼びかけ | 参加 | 合格 |
| 人間が回答し、解決済みの質問           | 黙る | 合格 |
| AIも含む冗談の続き                     | 参加 | 合格 |

使用モデルは設定上の`claude-sonnet-5-5`。5リクエスト、入力5688・出力234トークンで確認した。小さな人工会話での結果であり、実グループでの長期間の自然さを保証するものではない。

自動テストは宛先の違い、無投稿時の副作用、cooldown、先行回答・取り消し、再生成中の追加発言、削除・編集・forget・停止・reset、沈黙中の要約、DB移行、キュー上限を確認する。返答すべき場面と黙るべき場面の両方を含める。

## 6. 残る制約

- Discord上の実際の会話による継続評価と、本番の`ambient`切替は今回の検証に含めない。
- 参加の自然さはモデルの判断にも依存するため、5つの人工会話に加えて実運用で頻度・宛先・タイミングを確認する。
- Discord送信がすでに開始された後の新着・撤回を、送信と原子的に処理する仕組みはない。送信直前と分割投稿の各送信前に確認する。
- 送信成功とDB記録の間にプロセスが停止する曖昧状態について、完全な重複防止を保証するreconcileは未実装。
- 音声、画像理解、絵文字リアクション、複数話題の恒久的な分類は追加していない。
