# 操作を2つのコマンドへ整理

更新日: 2026-11-15。本番へ反映済み。

## 利用者の入口

| コマンド                | 用途                                   |
| ----------------------- | -------------------------------------- |
| `/ai`                   | 自分だけに見えるメニューを開く         |
| `/ai-image prompt:内容` | イラストを生成し、チャンネルへ投稿する |

`/ai`に引数やsubcommandは設けない。最初に見えるのは「自分の設定」「使い方・データ」と、管理者だけに見える「チャンネル設定」。通常のメニュー表示ではモデル確認APIを呼ばない。

## 操作のまとめ方

| 以前の操作                       | 新しい場所                                     |
| -------------------------------- | ---------------------------------------------- |
| 状態確認                         | メニュー冒頭の応答表示、管理者の「接続を確認」 |
| モード・停止・再開               | 「チャンネル設定」の応答選択                   |
| 文脈リセット・話題リセット       | 「チャンネル設定」→「話題を区切る」            |
| モデル・effort                   | 「チャンネル設定」の「速さ優先／じっくり」     |
| 呼び名・口調・長さ・プロフィール | 「自分の設定」                                 |
| データの説明・本人データ削除     | 「使い方・データ」→「データと削除」            |
| 問題報告                         | 「使い方・データ」→「問題を報告」              |

応答は「おまかせ」「呼んだときだけ」「停止」の3つ。旧`all`は`ambient`へ統合する。YAMLの旧値を読み替え、DBのoverride・停止前の復帰先も一度だけ移行する。停止中やmention指定は維持する。

返答設定は「速さ優先＝Haiku/medium」「じっくり＝Sonnet/high」の2つ。サーバー全体へ適用することを画面に示す。保存済みのモデルとeffortは選び直すまで維持する。YAMLと既存DBの詳細設定の読込能力は残し、通常の操作で5段階のeffortを選ばせない。

## 本人情報と権限

- メニュー、本人情報、操作結果、報告は非公開。画像生成の添付だけを共有する。
- 自己紹介の編集ボタンで返答への利用への同意を明示する。呼び名・自己紹介・公開リンク2件までを一つのフォームで編集する。リンク取得の既存SSRF対策はそのまま使う。
- ボタン・選択欄・フォームは本人IDへ結び付ける。管理操作は各interactionで権限と対象チャンネルを再検証する。
- データ削除・個人設定リセットは確認画面を挟む。確認は5分間・一度だけ有効で、キャンセルや他の操作で無効になる。
- プロフィール取得中に削除・リセット・別の編集があれば古い処理を取り消し、取得が後から完了しても再保存しない。
- 本人設定・プロフィールの変更と削除では、関係するチャンネルの生成中の文脈も無効化する。
- 問題報告は既存の運用DBへ記録し、利用者へ「運用ログに記録した」と表示する。別サービスへの送信はしない。

## 検証と配備

自動テスト150件、lint、Prettierが成功。コマンド2種類、メニューのpayload、権限、本人の識別、入力検証、削除の確認、プロフィールと削除の競合、モデル変更失敗、画像添付、Botのinteractionイベント配線を確認した。

配備時はBotを更新した後、Guildのコマンド定義を2種類へ一括更新する。`npm run register-commands -- --check`で登録結果を読み取り確認できる。復旧用に以前のイメージ・ソース・DB・コマンド定義を保存する。通常会話の投稿を使うテストは行わない。
