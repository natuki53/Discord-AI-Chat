## 1. 文書の目的

このディレクトリは、Discord の指定チャンネルへ常駐し、複数人の会話の流れを理解しながら自然に参加するローカル AI Bot の計画・仕様・設計をまとめる。

実装言語は JavaScript、実行環境は Node.js、文章生成は `home-server-2` 上の RTX 2060 6GB を利用するローカル LLM を前提とする。管理用 WebUI は作らず、設定ファイル、Discord の管理コマンド、CLI で管理する。

## 3. 設計の要点

- 設定されたチャンネルの人間による全メッセージを受信対象とする。
- チャンネル単位で処理順を直列化し、短時間の連投は一つの会話ターンとして束ねる。
- 直近の発言、返信関係、話者、会話セッション要約から「今の流れ」を理解する。
- `all` モードでは原則すべての会話ターンへ返答し、`ambient` モードでは自然に参加できる場合だけ返答する。
- ローカル LLM は Ollama 経由で呼び出し、モデル名は設定で交換可能にする。
- 時事性がある質問だけ Web 検索ツールを実行し、回答末尾へ参照 URL を付ける。
- Discord メッセージ履歴から個人の性格や人間関係を恒久的に推定・保存しない。
- 口調適応は現在の会話から一時的に行い、長期的な好みは本人が明示した設定だけを保存する。
- Bot のトークン、検索 API キー、外部サービスの認証情報はリポジトリへ保存しない。

## 4. 重要な制約

Discord Developer Policy は、API データを使った利用者や人間関係のプロファイリング、および Discord 上のデータのマイニング・スクレイピングを禁止している。そのため「サーバーの過去ログ全体を走査して各人の性格を作る」機能は本設計に含めない。

代わりに次の方法で求める体験を作る。

1. Bot 稼働中の現在の会話について、短期コンテキストと会話要約を保持する。
2. ネタ、口調、話題、呼びかけ先を現在の会話から読み、同じ流れに乗る。
3. 本人が `/ai-preferences` で明示した呼び名、回答の長さ、口調、ネタへの乗り方だけを長期保存する。
4. チャンネル全体の Bot ペルソナは管理者が明示的に設定する。

この境界を変更する場合は、実装前に Discord の最新ポリシーを再確認し、必要なら Discord から書面での許可を得る。

## 5. 想定用語

| 用語             | 意味                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| Guild            | Discord サーバー                                                             |
| 対象チャンネル   | Bot が受信・応答するよう allowlist へ登録したチャンネル                      |
| 会話ターン       | 連投を一定時間まとめた、AI が一度応答する処理単位                            |
| 会話セッション   | 同じ話題が継続している発言群                                                 |
| 短期コンテキスト | 直近メッセージと現在セッションの要約                                         |
| 明示設定         | 利用者本人または管理者がコマンドで指定した設定                               |
| ツール           | LLM が直接ネットワークへ出ず、アプリ側の制御下で実行する検索・ページ取得機能 |
